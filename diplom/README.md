## 📁 Об устройстве репозитория
Проект организован в изолированной директории `diplom` внутри общей структуры:
* `/.github/workflows/pipeline.yml` — Единый автоматический CI/CD сценарий деплоя (GitHub Actions).
* `/diplom/app` — Исходный код веб-приложения на Go и оптимизированный `Dockerfile` многоэтапной сборки.
* `/diplom/k8s` — Декларативные манифесты конфигурации ресурсов Kubernetes (`01-deployment.yaml`, `02-service.yaml`).

## 🛠️ По развёртыванию инфраструктуры

## 🚀 По развёртыванию приложения
Процесс поставки и обновления приложения полностью автоматизирован на основе практик CI/CD:
1. В настройках GitHub-репозитория (**Settings -> Secrets and variables -> Actions**) добавлены секреты окружения:
   * `DOCKERHUB_USERNAME` — Логин учетной записи Docker Hub (`alhagi`).
   * `DOCKERHUB_TOKEN` — Персональный токен доступа Docker Hub для авторизации.
   * `VPS_HOST` — Публичный IP-адрес сервера (`64.188.70.233`).
   * `VPS_SSH_KEY` — Секретный приватный SSH-ключ доступа к серверу.
2. При любом пуше (Push) в ветку `diploma-project` автоматически триггерится пайплайн GitHub Actions, который собирает бинарник, пакует контейнер, отправляет в реестр и обновляет поды в K3s через `kubectl apply`.

## ⚙️ О правилах внесения изменения в инфраструктуру
* Все изменения параметров контейнеров (лимиты процессора, памяти, внешние порты доступа NodePort или количество реплик) должны вноситься исключительно декларативно через редактирование манифестов внутри каталога `/diplom/k8s` в коде репозитория.
* Прямое ручное редактирование параметров работающих подов на сервере в обход Git запрещено во избежание рассинхронизации конфигураций (Концепция GitOps / Инфраструктура как код).

## 🔄 О релизном цикле приложения и правилах версионирования
* Разработка проекта ведется по упрощенной модели Git-Flow в ветке `diploma-project`.
* **Сборка (CI)**: Компилируемый Go-код упаковывается в Docker-контейнер с использованием Multi-stage подхода. Это гарантирует отсутствие тяжелых компиляторов в финальном образе, снижая его размер до ~15 МБ.
* **Версионирование артефактов**: Согласно регламенту аттестации, образы в Docker Hub маркируются уникальным хэш-идентификатором коммита (`sha-${{ github.sha }}`). Это позволяет однозначно связать работающий в Kubernetes контейнер с конкретным изменением в Git.
* **Логирование и Мониторинг**: Проверка состояния подов и логирование веб-сервера Authelia выполняются встроенными легковесными механизмами Kubernetes через утилиты `kubectl logs` и `kubectl get pods`.
